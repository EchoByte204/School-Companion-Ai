# CHITTI AI — Demo Credentials & Demo Data

## Which AI powers CHITTI AI?

CHITTI AI uses the **Lovable AI Gateway** (no API key needed, billed from workspace AI credits):

| Feature                      | Model                          |
| ---------------------------- | ------------------------------ |
| Chat / tools / role personas | `google/gemini-3.7-flash`      |
| Chat thread summaries        | `google/gemini-3.7-flash`      |
| Voice: speech-to-text        | gateway transcription endpoint |
| Voice: text-to-speech        | gateway speech endpoint        |

All model calls happen server-side (`src/routes/api/chat.ts`, `src/chitti-ai/server/*`), so the key
never reaches the browser.

### Why not local Ollama?

A local Ollama server (`qwen2.5:7b`, `phi3`, …) listens on `http://localhost:11434` **on your own
machine**. This app runs on Lovable's hosted edge runtime, which cannot reach your localhost, so a
hosted deployment would fail on every request. Options if you want Ollama:

1. Expose Ollama publicly (e.g. an ngrok/Cloudflare tunnel) and point the gateway base URL at it.
2. Run this repo locally and set an `OLLAMA_BASE_URL` env var.

Say the word and I'll add an `OLLAMA_BASE_URL` switch that falls back to Lovable AI when unset.

## Seeded demo data

- **Classes:** 10-A, 9-B, 9-C, 8-A with assigned class teachers.
- **Students:** roll numbers, guardian names and guardian emails for parent linking.
- **Attendance:** ~90 days of weekday history (present / absent / late) per student.
- **Support requests:** created live through the assistant's escalation tool; statuses
  pending → acknowledged → resolved → rejected, each firing a notification.
- **Notifications:** auto-generated by a DB trigger on request insert/status change.
- **Chat threads:** created per user, with AI-generated summaries on demand.
